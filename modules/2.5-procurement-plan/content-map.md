# Module 2.5 — Developing the procurement plan

**Target learner:** Project managers responsible for procurement decisions
**Duration target:** ~30 min
**Assessment strategy:** MCQ knowledge check

| Objective | Assessment | Practice | Presentation |
|-----------|------------|----------|--------------|
| **Differentiate** a procurement plan from a project plan by scope and purpose | MCQ: given 4 statements, classify each as procurement-plan scope or project-plan scope | — | **Slide 1 (L13):** Objectives — what you'll be able to do. **Slide 2 (L01):** Activate prior knowledge — "You already use a project plan. What does it cover?" List familiar project-plan elements (timeline, resources, deliverables). **Slide 3 (L03):** Introduce the new concept — "A procurement plan answers a different question: how will we buy?" Definition + visual showing procurement plan as a SUBSET document that feeds into the project plan. **Slide 4 (L01):** Contrast — side-by-side: "Project plan asks WHAT and WHEN. Procurement plan asks HOW we buy and FROM WHOM." 3 concrete scope examples per column so learner can pattern-match. |
| **Identify** the 8 components of a procurement plan and their role | MCQ: match 3 components to their function (from a list of 8) | Explore each component via menu hub — learner self-paces, must visit all 8 before proceeding | **Slide 5 (L01):** Organizing framework FIRST — "A procurement plan has 3 phases: Define (what to buy), Execute (how to buy), Govern (who decides)." This chunks 8 components into 3 groups so working memory can handle them. **Slide 6 (L12 menu hub):** 8 bars grouped under the 3 phases. Each bar opens a popup. Pop-ups use varied layouts based on content: objectives & criteria (bullets), scope & packaging (bullets + example), procurement method (decision tree), contract type (compare 2 options), evaluation approach (checklist), risk & contingency (scenario), schedule & milestones (timeline), governance & approvals (role matrix). Each popup ends with a key-message bar anchoring the one takeaway. |
| **Select** the appropriate contract type (fixed-price vs T&M) given project constraints | Scenario MCQ: "Given this project scenario, which contract type best fits and why?" | Contract-type popup (inside the menu hub) walks through the decision criteria before the MCQ asks learner to apply them | **Slide 7 (L09):** MCQ — scenario describes a project (scope well-defined, timeline fixed, vendor experienced). Learner selects contract type. Feedback explains WHY the correct type fits the scenario's constraints — reinforces the decision framework from the popup. **Slide 8 (L14):** Summary — 3 takeaways, one per objective. Triggers completion. |

## Quality checklist
- [x] Every objective starts with an action verb (differentiate, identify, select)
- [x] No "understand" / "know" / "be aware of"
- [x] Assessment is concretely specifiable (MCQ for all three)
- [x] Each row aligns end-to-end (objective ↔ assessment ↔ practice ↔ presentation)
- [x] Scope fits duration (~3 objectives × ~10 min = ~30 min)
- [x] Presentation column specifies slide-by-slide sequence with layout IDs
- [x] Cognitive sequencing: activate prior knowledge → introduce new concept → contrast → organize → explore → apply → summarize

## Notes
- Slide 2 activates schema (project plan) before introducing the new concept (procurement plan) — reduces cognitive load by anchoring to familiar
- Slide 5 provides the chunking framework (3 phases) BEFORE the 8-component menu hub — without this, 8 items overwhelm working memory
- Objective 3's practice is embedded in the menu hub (contract-type popup) — learner encounters the decision criteria during exploration, then applies them in the MCQ. This is intentional: the practice happens during Objective 2's exploration, creating a bridge
- Only MVP layouts used: L13, L01, L03, L12, L09, L14
